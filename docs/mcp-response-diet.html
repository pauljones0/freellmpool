Cut MCP context bloat 38–97% with a reusable response diet

MCP servers routinely dump tens of thousands of characters per tool call straight into your context window. freellmpool ships a reusable output diet — a drop-in stdio proxy plus a Python wrapper — that compacts oversized tool results to a fixed budget with zero silent truncations. Below are measured before/after numbers on popular third-party MCP servers, not projections.

pip install freellmpool
python -m freellmpool.mcp_diet --budget 2000 -- \
    npx -y @modelcontextprotocol/server-filesystem /data

1. Wrap a server you don't control (any language)

Point your MCP client at the proxy instead of the server. It relays JSON-RPC both ways, compacts oversized text results in flight, and answers "_full": true re-calls from cache. Images, resources, notifications, and errors relay untouched:

python -m freellmpool.mcp_diet --budget 2000 -- \
    uvx mcp-server-fetch

2. Compact inside your own server (Python)

from freellmpool.mcp_diet import compact_content

result["content"] = compact_content(result["content"], 2000,
                                    label="quarterly report")

FAQ

What happens to small results?

They pass through byte-identical. The directory listing above (1,130 chars) was returned untouched — only over-budget text blocks are cut.

How do I get the full text back?

Re-run the same tool call with the extra argument "_full": true. The proxy serves the cached full result; a first-time "_full" call with nothing cached passes through to the server uncompacted.

Does it change non-text content?

No. Image and resource blocks, error responses, notifications, and the tool schemas themselves relay untouched. Only oversized text blocks are compacted.
